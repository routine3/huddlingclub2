# Korean Code Comments

코딩 초보자가 코드를 따라갈 수 있도록 파일 안의 어려운 부분에만 간결한 한국어 설명 주석을 추가한다.

## 작업 절차

1. 사용자가 지정한 경로가 프로젝트 내부의 실제 코드 파일인지 확인한다.
2. 프로젝트의 `AGENTS.md`와 대상 파일 전체를 읽고, 필요한 경우 대상 파일이 직접 사용하는 타입이나 함수만 추가로 확인한다.
3. 아래 기준에 해당하는 이해하기 어려운 부분을 찾는다.
   - 데이터가 변환되거나 여러 단계를 거쳐 전달되는 흐름
   - 비동기 처리, 예외 처리, 상태 변경 또는 프레임워크 생명주기
   - 결과만 보고 의도를 알기 어려운 조건문, 정규식, 알고리즘 또는 타입
   - 보안이나 데이터 무결성을 위해 반드시 지켜야 하는 제약
4. 코드 언어에 맞는 주석 문법으로, 해당 코드 바로 가까이에 한국어 주석을 추가한다.
5. 변경 전후 차이를 확인하여 실행 코드, 타입, 문자열, 포맷이 의도치 않게 바뀌지 않았는지 검토한다.
6. 프로젝트에서 사용할 수 있는 가장 가까운 정적 검사나 테스트를 실행한다. 이 프로젝트에서는 기본적으로 `npm run lint`를 사용하고, 변경 위험이 있으면 빌드도 확인한다.

## 주석 작성 기준

- 코드가 **무엇을 하는지** 반복하기보다 **왜 필요한지**, **어떤 순서로 동작하는지**, **주의할 점이 무엇인지**를 쉬운 한국어로 설명한다.
- 한 주석에는 한 가지 핵심만 담고, 처음 배우는 사람도 이해할 수 있는 짧은 문장을 사용한다.
- 변수 대입, 단순 반환, 명확한 JSX처럼 코드만 읽어도 알 수 있는 부분에는 주석을 달지 않는다.
- 모든 줄을 번역하듯 설명하거나 큰 주석 블록으로 파일을 덮지 않는다.
- 기존에 정확한 주석이 있다면 중복해서 추가하지 않는다. 오래되었거나 코드와 충돌하는 기존 주석은 사용자의 요청 없이 임의로 고치지 말고 먼저 알린다.
- 함수의 사용 계약이나 공개 API 설명이 필요할 때만 JSDoc/TSDoc을 사용한다. 일반 로직 설명은 가까운 인라인 또는 블록 주석을 사용한다.
- 기술 용어가 꼭 필요하면 주석 안에서 짧게 뜻을 풀어 쓴다.

## 확인이 필요한 경우

다음 상황에서는 추측한 설명을 코드에 넣지 말고 사용자에게 구체적으로 질문한다.

- 코드와 주변 문맥만으로 함수나 값의 업무상 의미를 확정할 수 없는 경우
- 서로 다른 두 가지 이상의 의도로 해석될 수 있는 로직인 경우
- 버그처럼 보이는 동작을 현재 의도라고 설명해야 하는지 불분명한 경우
- 사용자가 원하는 주석 범위가 파일 전체인지 특정 함수인지 알 수 없는 경우
- 주석 추가만으로 부족하고 리팩터링이나 코드 수정이 필요해 보이는 경우

질문에 답을 받기 전에는 확인되지 않은 내용을 사실처럼 적지 않는다. 확인 가능한 부분의 분석은 계속할 수 있지만, 불확실한 주석은 보류한다.

## 변경 제한

- 이 스킬은 주석 추가만 수행한다. 코드 로직, 공개 API, 변수명, 타입, 스타일 또는 파일 구조를 변경하지 않는다.
- 사용자가 리팩터링이나 버그 수정도 명시적으로 요청한 경우에는 주석 작업과 코드 변경을 구분해 진행한다.
- 비밀번호, API 키, 개인 정보 같은 민감한 값을 주석에 복사하거나 설명을 위해 노출하지 않는다.
- 생성 파일, 외부 라이브러리, 잠금 파일, 빌드 결과물에는 주석을 추가하지 않는다. 사용자가 그런 파일을 지정하면 원본 소스 파일을 요청한다.

## 완료 보고

- 수정한 파일 경로를 알려준다.
- 어떤 어려운 부분에 어떤 목적의 주석을 추가했는지 짧게 요약한다.
- 실행한 검사와 결과를 알리고, 검증하지 못한 항목이 있으면 이유를 설명한다.
